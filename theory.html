1Foundation Model Integration, Data Management, and Compliance 31%

Domain nặng ký nhất: thiết kế giải pháp, chọn/cấu hình FM, xử lý dữ liệu cho FM, vector store, retrieval, và prompt engineering/governance.

Task 1.1Phân tích yêu cầu và thiết kế giải pháp GenAI

Trước khi chọn công nghệ cụ thể, cần xây thiết kế kiến trúc phù hợp với ràng buộc nghiệp vụ/kỹ thuật, và xác thực bằng proof-of-concept (PoC) trên Amazon Bedrock trước khi triển khai quy mô lớn. AWS khuyến nghị dùng AWS Well-Architected Framework và riêng AWS WA Tool Generative AI Lens để chuẩn hóa các thành phần kỹ thuật (bảo mật, RAG, observability) tái sử dụng nhất quán qua nhiều dự án — đây cũng là căn cứ hay gặp trong các câu hỏi về "chuẩn hóa triển khai xuyên nhiều business unit".

Task 1.2Lựa chọn và cấu hình FM

Amazon Bedrock là dịch vụ fully-managed cho phép truy cập nhiều foundation model (FM) từ nhiều nhà cung cấp (Anthropic Claude, Amazon Nova, Amazon Titan...) qua một API thống nhất. Việc chọn FM cần dựa trên performance benchmark, phân tích năng lực, và đánh giá giới hạn của từng model.

  • Kiến trúc chuyển đổi model động — dùng Lambda + API Gateway + AWS AppConfig để đổi FM/nhà cung cấp mà không cần sửa/deploy lại code.
  • Khả năng phục hồi (resilience) — dùng mẫu circuit breaker trong Step Functions, Cross-Region Inference (CRI) cho model có phạm vi Region hạn chế, triển khai đa Region, và chiến lược graceful degradation (giảm cấp độ dịch vụ có kiểm soát thay vì sập hoàn toàn) khi có gián đoạn.
  • Tùy biến & vòng đời model — dùng Amazon SageMaker AI để triển khai model fine-tune theo domain; kỹ thuật parameter-efficient fine-tuning như LoRA (Low-Rank Adaptation) và adapter giúp tùy biến model với chi phí huấn luyện thấp hơn nhiều so với fine-tune toàn bộ tham số; dùng SageMaker Model Registry để version hóa và triển khai model tùy biến; có pipeline triển khai tự động, chiến lược rollback khi thất bại, và quy trình quản lý vòng đời để retire/thay thế model cũ.

Task 1.3Triển khai pipeline kiểm tra và xử lý dữ liệu để FM tiêu thụ

Trước khi dữ liệu tới được FM, cần một pipeline xử lý riêng biệt:

  • Kiểm tra chất lượng dữ liệu — dùng AWS Glue Data Quality hoặc SageMaker Data Wrangler để validate dữ liệu trước khi đưa vào FM, kết hợp CloudWatch metrics để giám sát.
  • Xử lý dữ liệu đa phương thức (multimodal) — văn bản, hình ảnh, âm thanh, dữ liệu dạng bảng đều cần xử lý chuyên biệt: Bedrock multimodal model, SageMaker Processing, Amazon Transcribe (audio → text) là các thành phần thường gặp.
  • Định dạng đầu vào theo đúng yêu cầu model — format JSON cho Bedrock API request, chuẩn bị dữ liệu có cấu trúc cho SageMaker AI endpoint, định dạng hội thoại (message array) cho ứng dụng dialog.
  • Nâng cao chất lượng dữ liệu đầu vào — dùng Bedrock để định dạng lại văn bản, Amazon Comprehend để trích xuất thực thể, Lambda function để chuẩn hóa dữ liệu — nhằm cải thiện chất lượng và tính nhất quán của phản hồi FM ngay từ đầu vào, thay vì chỉ xử lý ở đầu ra.

Task 1.4 & 1.5Vector store & Cơ chế truy xuất (RAG)

RAG (Retrieval Augmented Generation) là kỹ thuật truy xuất thông tin liên quan từ kho dữ liệu ngoài rồi đưa vào prompt để FM sinh câu trả lời có căn cứ (grounded), giảm hallucination và cho phép trả lời dựa trên dữ liệu riêng/mới.

  • Amazon Bedrock Knowledge Bases — dịch vụ managed để xây RAG: tự ingest tài liệu, chunk, tạo embedding, lưu vector, cung cấp API Retrieve/RetrieveAndGenerate(Stream) kèm source attribution/citation tự động. Hỗ trợ tổ chức phân cấp (hierarchical) cho tài liệu lớn.
  • Lựa chọn vector database — Amazon OpenSearch Service (Neural plugin tích hợp Bedrock, sharding để scale), Amazon Aurora PostgreSQL + pgvector (khi đã có sẵn dữ liệu quan hệ), Amazon RDS + S3 (kho tài liệu), Amazon DynamoDB kết hợp vector database cho metadata/embedding.
  • Metadata framework — S3 object metadata cho timestamp, thuộc tính tùy chỉnh cho tác giả, tagging để phân loại domain — cải thiện độ chính xác tìm kiếm mà không cần đọc toàn bộ nội dung tài liệu.
  • Chunking strategy — fixed-size chunking (đơn giản, dễ cắt đứt ngữ cảnh), semantic chunking (theo ranh giới ngữ nghĩa), hierarchical chunking (chunk cha/con, dựa trên cấu trúc nội dung).
  • Embedding — Amazon Titan Embeddings hoặc các embedding model khác trên Bedrock, chọn theo số chiều (dimensionality) và mức phù hợp domain; dùng Lambda để tạo embedding hàng loạt (batch).
  • Nâng cao độ liên quan truy xuất — hybrid search (kết hợp vector + từ khóa), reranking (Amazon Bedrock reranker model sắp xếp lại kết quả theo độ liên quan thực sự), query expansion (mở rộng truy vấn), query decomposition (phân rã truy vấn phức tạp thành nhiều truy vấn nhỏ qua Lambda), query transformation (biến đổi truy vấn qua Step Functions).
  • Truy cập nhất quán cho FM — function calling interface cho vector search, Model Context Protocol (MCP) client cho truy vấn vector, mẫu API chuẩn hóa cho retrieval augmentation.
  • Bảo trì vector store — cơ chế cập nhật tăng dần, phát hiện thay đổi real-time, đồng bộ tự động, pipeline làm mới theo lịch để đảm bảo dữ liệu trong vector store luôn hiện hành.
Bẫy thường gặp: tài liệu bị cắt sai ranh giới ngữ nghĩa (ví dụ lập luận pháp lý bị chia rời) → đáp án đúng là đổi chunking strategy sang semantic/hierarchical rồi tạo lại embedding — KHÔNG phải chỉ tăng số chiều vector hay đổi datastore. Khi vector search bỏ sót thuật ngữ/mã viết tắt chính xác → ưu tiên hybrid search, không phải tăng dimensionality.

Task 1.6Prompt Engineering & Governance

  • Kỹ thuật viết prompt — zero-shot, one-shot/few-shot, chain-of-thought (CoT) (yêu cầu suy luận từng bước để tăng độ chính xác), system prompt để định hình vai trò/giọng văn xuyên suốt hội thoại.
  • Amazon Bedrock Prompt Management — quản lý version, biến (variables), biến thể (variants) của prompt template tập trung; hỗ trợ workflow phê duyệt và audit trail (CloudTrail để theo dõi sử dụng, CloudWatch Logs để ghi log truy cập) — phù hợp khi cần quản trị hàng trăm prompt dùng chung nhiều team.
  • Amazon Bedrock Prompt Flows — công cụ kéo-thả xây pipeline nhiều bước (input → prompt → output node), hỗ trợ phân nhánh có điều kiện dựa trên phản hồi model, thành phần prompt tái sử dụng, và bước tiền/hậu xử lý tích hợp — không cần code orchestration thủ công.
  • Hệ thống AI tương tác đa lượt (multi-turn) — Step Functions cho workflow làm rõ (clarification) khi câu hỏi người dùng mơ hồ, Amazon Comprehend để nhận diện ý định, DynamoDB để lưu lịch sử hội thoại.
  • QA cho prompt — Lambda function để xác minh đầu ra mong đợi, Step Functions để test edge case, CloudWatch để test hồi quy (regression) khi thay đổi prompt.
Câu hỏi kiểu "quản lý hàng trăm prompt qua nhiều team, cần version control + approval workflow + audit trail, ít chi phí vận hành nhất" → đáp án gần như luôn là Bedrock Prompt Management, không phải tự dựng bằng S3 + Step Functions + EventBridge.

2Implementation and Integration 26%

Agentic AI, chiến lược deploy model, kiến trúc tích hợp doanh nghiệp, tích hợp API FM, và công cụ phát triển.

Task 2.1Agentic AI & Tích hợp công cụ

  • Amazon Bedrock Agents — FM tự lập kế hoạch, gọi action group (Lambda/API) và tra cứu knowledge base để hoàn thành nhiệm vụ nhiều bước; bật trace events để ghi lại từng bước suy luận phục vụ audit.
  • ReAct pattern (Reasoning + Acting) và chain-of-thought — Step Functions triển khai các bước suy luận có cấu trúc để FM phân rã và giải quyết vấn đề phức tạp.
  • Strands Agents và AWS Agent Squad — framework mã nguồn mở do AWS phát triển để xây hệ thống multi-agent với quản lý memory/state, dùng MCP cho tương tác agent–công cụ; Strands API cho phép định nghĩa hành vi tùy chỉnh và hàm chuẩn hóa cho tool integration.
  • An toàn cho agent (safeguarded workflow) — Step Functions để định nghĩa điều kiện dừng, Lambda để triển khai timeout, IAM policy để giới hạn tài nguyên agent được phép truy cập, circuit breaker để giảm thiểu lỗi lan truyền khi một bước trong chuỗi agent thất bại liên tục.
  • Model Context Protocol (MCP) — giao thức chuẩn hóa cách agent kết nối tới công cụ/nguồn dữ liệu ngoài. Có thể host MCP server bằng Lambda (stateless, nhẹ) hoặc Amazon ECS (cho công cụ phức tạp, cần trạng thái); dùng Streamable HTTP transport sau API Gateway + OAuth 2.1 khi cần expose cho đối tác ngoài, hoặc STDIO transport khi chỉ chạy nội bộ.
  • Human-in-the-loop — Step Functions điều phối quy trình review/phê duyệt (waitForTaskToken / SendTaskSuccess), API Gateway để thu thập phản hồi con người bổ sung cho năng lực FM.

Task 2.2Chiến lược deploy model

  • On-Demand vs Provisioned Throughput — On-Demand trả theo token, dễ bị throttle khi vượt hạn mức; Provisioned Throughput (đo bằng Model Unit — MU) mua trước công suất cố định cho tải cao ổn định, tạo qua CreateProvisionedModelThroughput.
  • Thách thức triển khai LLM khác ML truyền thống — mẫu container cần tối ưu riêng cho yêu cầu bộ nhớ, sử dụng GPU, và năng lực xử lý token; cần chiến lược load model chuyên biệt (model lớn, thời gian khởi động lâu hơn nhiều so với model ML cổ điển).
  • Tối ưu triển khai theo tải — chọn model nhỏ/pre-trained cho tác vụ đơn giản, dùng model cascading dựa trên API (định tuyến câu hỏi đơn giản tới model nhỏ, phức tạp tới model lớn) để cân bằng hiệu năng và chi phí.
  • SageMaker AI endpoint — real-time (độ trễ thấp, GPU chuyên dụng), serverless (scale-to-zero, tải không đều), asynchronous (payload lớn/xử lý lâu) — dùng để triển khai giải pháp hybrid cùng Bedrock.

Task 2.3Kiến trúc tích hợp doanh nghiệp

  • Kết nối doanh nghiệp — tích hợp dựa trên API với hệ thống legacy, kiến trúc event-driven (EventBridge) để tách rời lỏng lẻo (loose coupling), mẫu đồng bộ dữ liệu giữa các hệ thống.
  • Truy cập an toàn — identity federation giữa dịch vụ FM và hệ thống doanh nghiệp, role-based access control, nguyên tắc least privilege cho mọi API access tới FM.
  • Giải pháp đa môi trường / hybrid — AWS Outposts để tích hợp dữ liệu on-premises, AWS Wavelength để triển khai edge, định tuyến an toàn giữa cloud và on-premises — dùng khi dữ liệu phải tuân thủ theo từng khu vực pháp lý (data residency) mà vẫn cần truy cập FM.
  • CI/CD & GenAI gateway — AWS CodePipeline, AWS CodeBuild, khung kiểm thử tự động cho việc triển khai/kiểm thử liên tục thành phần GenAI kèm quét bảo mật và hỗ trợ rollback; lớp trừu tượng hóa tập trung (gateway) cùng cơ chế quan sát/kiểm soát cho việc tiêu thụ GenAI trong tổ chức.

Task 2.4Tích hợp API cho FM

  • Đồng bộ vs bất đồng bộ — Bedrock API cho request đồng bộ từ nhiều môi trường compute; AWS SDK theo từng ngôn ngữ + Amazon SQS cho xử lý bất đồng bộ.
  • Streaming thời gian thực — InvokeModelWithResponseStream/ConverseStream, WebSocket hoặc server-sent event để sinh văn bản theo thời gian thực; API Gateway hỗ trợ chunked transfer encoding.
  • Khả năng phục hồi — AWS SDK với exponential backoff, API Gateway để quản lý rate limiting, cơ chế fallback cho graceful degradation, AWS X-Ray để quan sát xuyên suốt ranh giới dịch vụ (đâu là điểm gây latency khi request đi qua nhiều service).
  • Định tuyến model thông minh — định tuyến tĩnh trong code, Step Functions cho định tuyến động dựa trên nội dung, hoặc Bedrock Intelligent Prompt Routing để tự động chọn model theo độ phức tạp câu hỏi.

Task 2.5Mẫu tích hợp ứng dụng & công cụ phát triển

  • Giao diện dễ tiếp cận — AWS Amplify để xây UI khai báo (declarative), đặc tả OpenAPI cho cách tiếp cận API-first, Bedrock Prompt Flows cho workflow builder no-code.
  • Tăng năng suất developer — Amazon Q Developer để sinh/tái cấu trúc code, gợi ý code hỗ trợ API, kiểm thử thành phần AI, tối ưu hiệu năng, và nhận diện mẫu lỗi đặc thù GenAI.
  • Cải tiến hệ thống nghiệp vụ — Lambda cho CRM, Step Functions điều phối xử lý tài liệu, Amazon Bedrock Data Automation để tự động hóa quy trình xử lý dữ liệu.
  • Troubleshooting — CloudWatch Logs Insights để phân tích prompt/phản hồi, X-Ray để trace lệnh gọi API FM.

3AI Safety, Security, and Governance 20%

Kiểm soát an toàn đầu vào/đầu ra, bảo mật & quyền riêng tư dữ liệu, quản trị/tuân thủ, và nguyên tắc Responsible AI.

Task 3.1Kiểm soát an toàn đầu vào/đầu ra

  • Amazon Bedrock Guardrails — content filter (chặn nội dung độc hại theo danh mục, ngưỡng low/medium/high), denied topics (chủ đề bị cấm hoàn toàn kèm câu ví dụ mẫu), word filter (danh sách từ/cụm từ tùy chỉnh), sensitive information filter (PII: mask hoặc block).
  • Giảm hallucination — Bedrock Knowledge Base để "ground" câu trả lời và fact-checking; chấm điểm độ tin cậy (confidence scoring) và tìm kiếm tương đồng ngữ nghĩa để xác minh; JSON Schema để ép buộc đầu ra có cấu trúc, giảm khả năng model "bịa" định dạng tự do.
  • Phòng thủ theo chiều sâu (defense-in-depth) — Amazon Comprehend cho bộ lọc tiền xử lý, Bedrock guardrail dựa trên model, Lambda validate hậu xử lý, API Gateway lọc phản hồi API — nhiều lớp bảo vệ độc lập.
  • Phát hiện mối đe dọa nâng cao — cơ chế phát hiện prompt injection và jailbreak, làm sạch đầu vào, bộ phân loại an toàn (safety classifier), quy trình kiểm thử đối kháng (adversarial testing) tự động.

Task 3.2Bảo mật & quyền riêng tư dữ liệu

  • Cô lập mạng — VPC endpoint (interface endpoint) cho Amazon Bedrock đảm bảo lệnh gọi đi qua đường truyền private, không qua internet công cộng.
  • Kiểm soát truy cập dữ liệu — IAM policy cho mẫu truy cập an toàn, AWS Lake Formation (LF-Tags) để cấp quyền dữ liệu chi tiết ở mức cột/bảng xuyên nhiều tài khoản, CloudWatch để giám sát truy cập dữ liệu.
  • Bảo vệ PII — Amazon Comprehend và Amazon Macie để phát hiện PII, tính năng bảo mật dữ liệu gốc của Bedrock, Bedrock guardrail để lọc đầu ra, S3 Lifecycle để thực thi chính sách lưu trữ.
  • Kỹ thuật bảo vệ quyền riêng tư — data masking, anonymization cho thông tin nhạy cảm, kết hợp Bedrock guardrail để vẫn giữ tính hữu dụng của FM trong khi bảo vệ quyền riêng tư người dùng.

Task 3.3Quản trị và tuân thủ AI

  • Model card — SageMaker AI hỗ trợ tạo model card theo chương trình (programmatic) để ghi lại giới hạn, mục đích sử dụng, và đặc tính của FM — phục vụ tuân thủ quy định.
  • Data lineage (phả hệ dữ liệu) — AWS Glue tự động theo dõi nguồn gốc dữ liệu; AWS Glue Data Catalog đăng ký nguồn dữ liệu; gắn tag metadata để phân bổ nguồn cho nội dung do FM sinh ra — AWS CloudTrail ghi log audit cho toàn bộ quá trình truy cập.
  • Giám sát quản trị nâng cao — phát hiện tự động cho lạm dụng/drift/vi phạm chính sách, giám sát bias drift, quy trình cảnh báo & khắc phục tự động, ẩn thông tin ở cấp token (token-level redaction), ghi log phản hồi, bộ lọc chính sách đầu ra AI.

Task 3.4Nguyên tắc Responsible AI

  • Minh bạch (transparency) — hiển thị suy luận (reasoning display) cho người dùng, CloudWatch thu thập metric độ tin cậy và định lượng độ không chắc chắn, Bedrock agent tracing cung cấp dấu vết suy luận.
  • Đánh giá công bằng (fairness) — metric công bằng định trước trong CloudWatch (ví dụ dùng Amazon SageMaker Clarify để phân tích bias), Bedrock Prompt Management/Prompt Flows để A/B testing có hệ thống, LLM-as-a-judge để đánh giá model tự động.
  • Tuân thủ chính sách — Bedrock guardrail dựa trên yêu cầu chính sách nội bộ, model card ghi lại giới hạn của FM, Lambda function để kiểm tra tuân thủ tự động.
Khi cần nhiều mức xử lý khác nhau cho nhiều loại nội dung nhạy cảm → thường chỉ cần MỘT guardrail cấu hình đa chính sách, không cần nhiều guardrail nối chuỗi bằng Step Functions.

4Operational Efficiency and Optimization for GenAI Applications 12%

Tối ưu chi phí/tài nguyên, tối ưu hiệu năng ứng dụng, và giám sát vận hành cho ứng dụng GenAI.

Task 4.1Tối ưu chi phí & hiệu quả tài nguyên

  • Tối ưu token — ước tính/theo dõi token trước khi gửi request, tối ưu context window, kiểm soát kích thước phản hồi, prompt compression (nén prompt), context pruning (cắt tỉa ngữ cảnh không cần thiết), giới hạn độ dài phản hồi.
  • Lựa chọn model tiết kiệm chi phí — đánh đổi chi phí-năng lực, phân tầng sử dụng FM theo độ phức tạp truy vấn (model routing), đo tỷ lệ giá/hiệu năng.
  • Tối đa hóa throughput — chiến lược batching, lập kế hoạch capacity, auto-scaling, tối ưu provisioned throughput.
  • Caching thông minh — semantic caching (cache theo độ tương đồng ngữ nghĩa của câu hỏi, không chỉ khớp chuỗi chính xác), result fingerprinting, edge caching, băm request tất định (deterministic hashing), prompt caching (cache phần ngữ cảnh lặp lại giữa các lần gọi) — đều nhằm tránh gọi FM không cần thiết.

Task 4.2Tối ưu hiệu năng ứng dụng

  • Giảm độ trễ — pre-computation cho truy vấn có thể dự đoán, model Bedrock latency-optimized cho ứng dụng nhạy cảm thời gian, request song song cho workflow phức tạp, response streaming.
  • Hiệu năng truy xuất — tối ưu index, tiền xử lý truy vấn, hybrid search với chấm điểm tùy chỉnh.
  • Tối ưu throughput FM — tối ưu xử lý token, batch inference, quản lý gọi model đồng thời (concurrent).
  • Tinh chỉnh tham số — cấu hình riêng theo model, A/B testing, lựa chọn temperature và top-k/top-p phù hợp theo yêu cầu (nhớ: KHÔNG tăng temperature để giảm hallucination).
  • Phân bổ tài nguyên & giao tiếp dịch vụ hiệu quả — capacity planning cho token processing, auto-scaling tối ưu theo mẫu traffic GenAI, tối ưu truy vấn vector database cho retrieval augmentation.

Task 4.3Giám sát vận hành cho ứng dụng GenAI

  • Observability toàn diện — metric vận hành, tracing hiệu năng/tương tác FM, metric tác động kinh doanh với dashboard tùy chỉnh (CloudWatch, Amazon Managed Grafana, Amazon QuickSight).
  • Giám sát đặc thù GenAI — CloudWatch theo dõi mức sử dụng token, hiệu quả prompt, tỷ lệ hallucination, chất lượng phản hồi; anomaly detection cho mẫu bùng nổ token và response drift; Amazon Bedrock Model Invocation Logs để phân tích chi tiết request/response; phát hiện bất thường chi phí.
  • Giám sát hiệu năng công cụ (tool) — theo dõi mẫu gọi, thu thập metric hiệu năng, quan sát tool calling và điều phối multi-agent, baseline sử dụng để phát hiện bất thường.
  • Vận hành vector store — giám sát hiệu năng vector database, quy trình tối ưu index tự động, validate chất lượng dữ liệu định kỳ.
  • Nhận diện lỗi đặc thù GenAI (không có trong ML truyền thống) — golden dataset để phát hiện hallucination (so sánh với bộ câu trả lời chuẩn đã biết), output diffing để phân tích tính nhất quán phản hồi giữa các lần gọi, reasoning path tracing để nhận diện lỗi logic trong chuỗi suy luận.

5Testing, Validation, and Troubleshooting 11%

Hệ thống đánh giá (evaluation) cho GenAI và xử lý sự cố (troubleshooting) ứng dụng GenAI.

Task 5.1Hệ thống đánh giá cho GenAI

  • Metric vượt ngoài ML truyền thống — độ liên quan (relevance), độ chính xác thực tế (factual accuracy), tính nhất quán (consistency), độ trôi chảy (fluency).
  • Amazon Bedrock Model Evaluations — A/B testing và canary testing cho FM, đánh giá đa model, phân tích chi phí-hiệu năng (hiệu quả token, tỷ lệ độ trễ/chất lượng, kết quả kinh doanh).
  • Đánh giá lấy người dùng làm trung tâm — giao diện phản hồi, hệ thống chấm điểm, quy trình gán nhãn (annotation) để đánh giá chất lượng phản hồi.
  • QA có hệ thống — workflow đánh giá liên tục, kiểm thử hồi quy (regression) cho đầu ra model, cổng chất lượng tự động (quality gate) trước khi deploy.
  • Đánh giá đa góc độ — đánh giá RAG (context relevance/coverage/faithfulness), LLM-as-a-Judge, thu thập phản hồi con người.
  • Đánh giá retrieval — chấm điểm độ liên quan, xác minh khớp ngữ cảnh, đo độ trễ truy xuất.
  • Đánh giá agent — tỷ lệ hoàn thành tác vụ, hiệu quả sử dụng công cụ, Amazon Bedrock Agent evaluation, chất lượng suy luận trong workflow nhiều bước.
  • Validate khi cập nhật FM — luồng công việc người dùng mô phỏng (synthetic), validate riêng cho AI về tỷ lệ hallucination và semantic drift trước/sau khi đổi phiên bản model.

Task 5.2Xử lý sự cố (troubleshoot) ứng dụng GenAI

  • Vấn đề xử lý nội dung — chẩn đoán tràn context window, chiến lược chunking động, tối ưu thiết kế prompt, phân tích lỗi liên quan đến truncation (câu trả lời bị cắt cụt do vượt giới hạn token).
  • Vấn đề tích hợp API FM — ghi log lỗi, validate request, phân tích phản hồi để nhận diện lỗi tích hợp đặc thù GenAI (khác lỗi tích hợp API thông thường).
  • Vấn đề prompt engineering — khung kiểm thử prompt, so sánh phiên bản (version comparison), tinh chỉnh có hệ thống thay vì sửa mò.
  • Vấn đề hệ thống truy xuất — phân tích độ liên quan phản hồi model, chẩn đoán chất lượng embedding, giám sát drift, khắc phục lỗi vector hóa/chunking/tiền xử lý, tối ưu hiệu năng vector search.
  • Bảo trì prompt — kiểm thử template + CloudWatch Logs để chẩn đoán prompt gây nhầm lẫn, X-Ray để xây pipeline quan sát prompt, validate schema để phát hiện lỗi không nhất quán định dạng.

Bảng thuật ngữ AWS (Glossary)

Tra cứu nhanh toàn bộ dịch vụ/API/khái niệm AWS xuất hiện trong bộ đề và trong Exam Guide chính thức. Gõ để lọc.

Generative AI / Bedrock

Amazon Bedrock
Dịch vụ fully-managed truy cập nhiều foundation model qua một API thống nhất, không cần tự vận hành hạ tầng GPU.
Foundation Model (FM)
Mô hình nền tảng quy mô lớn (LLM, mô hình đa phương thức...) được huấn luyện trước, dùng chung cho nhiều tác vụ.
Amazon Bedrock Guardrails
Lớp kiểm soát an toàn nội dung: content filter, denied topics, PII filter, contextual grounding check, word filter.
Amazon Bedrock Knowledge Bases
Dịch vụ RAG managed: tự ingest, chunk, tạo embedding, lưu vector và cung cấp API truy xuất/sinh câu trả lời.
Amazon Bedrock Agents
Cho phép FM tự lập kế hoạch và gọi công cụ (action group) hoặc knowledge base để hoàn thành nhiệm vụ nhiều bước.
Amazon Bedrock AgentCore
Runtime cho agent production-grade với memory, identity, event handling, observability tích hợp sẵn.
Amazon Bedrock Prompt Flows
Công cụ kéo-thả xây pipeline nhiều bước (input/prompt/output node) không cần code orchestration.
Amazon Bedrock Prompt Management
Quản lý version, biến, biến thể của prompt template tập trung kèm workflow phê duyệt & audit trail.
Bedrock Intelligent Prompt Routing
Tự động định tuyến câu hỏi đơn giản tới mô hình nhỏ, câu hỏi phức tạp tới mô hình lớn để tối ưu chi phí.
Cross-Region Inference (CRI)
Định tuyến request tự động qua một tập Region khác để tăng khả năng chịu tải, vẫn giữ dữ liệu trong khu vực pháp lý cho phép.
Provisioned Throughput / Model Unit (MU)
Mua trước công suất cố định để đảm bảo throughput ổn định cho tải cao liên tục, tạo qua CreateProvisionedModelThroughput.
Amazon Bedrock Model Evaluations
Tạo evaluation job so sánh FM/prompt bằng metric tự động (kể cả LLM-as-a-judge) hoặc đánh giá của con người.
Amazon Bedrock Rerank
Sắp xếp lại kết quả truy xuất RAG theo mức độ liên quan thực sự trước khi đưa vào FM.
Amazon Bedrock Data Automation
Tự động hóa quy trình xử lý dữ liệu (trích xuất, chuẩn hóa) để phục vụ ứng dụng GenAI.
InvokeModel / InvokeModelWithResponseStream
API gọi FM đồng bộ (trả toàn bộ kết quả) hoặc dạng stream (trả từng phần theo thời gian thực).
Converse API / ConverseStream
API hội thoại chuẩn hóa format giữa nhiều FM, hỗ trợ multi-turn qua mảng messages.
Retrieve / RetrieveAndGenerate(Stream)
API của Knowledge Bases: chỉ truy xuất tài liệu, hoặc truy xuất + sinh câu trả lời kèm trích dẫn nguồn.
Amazon Titan
Dòng foundation model của AWS, bao gồm Titan Embeddings dùng để tạo vector embedding.
Temperature / top-k / top-p
Tham số điều chỉnh mức ngẫu nhiên/đa dạng của đầu ra mô hình; temperature cao hơn dễ gây hallucination hơn.
Chain-of-Thought (CoT)
Kỹ thuật prompt yêu cầu mô hình suy luận từng bước trước khi kết luận để tăng độ chính xác.
Prompt caching
Lưu lại phần ngữ cảnh lặp lại giữa các lần gọi để giảm chi phí và độ trễ.
Semantic caching
Cache câu trả lời theo độ tương đồng ngữ nghĩa của câu hỏi, không chỉ khớp chuỗi chính xác, giúp giảm gọi FM trùng lặp.
Prompt compression / Context pruning
Kỹ thuật rút gọn hoặc cắt tỉa phần ngữ cảnh không cần thiết trong prompt để giảm chi phí token.
Hallucination
Hiện tượng mô hình sinh ra nội dung sai sự thật hoặc không có căn cứ trong nguồn dữ liệu.
Grounding / Contextual grounding check
Cơ chế đối chiếu câu trả lời với nguồn tham chiếu để phát hiện hallucination.
LLM-as-a-judge
Dùng một FM khác (thường mạnh hơn) để tự động chấm điểm chất lượng câu trả lời theo tiêu chí.
Golden dataset
Bộ dữ liệu câu hỏi/câu trả lời chuẩn đã biết trước, dùng làm mốc so sánh để phát hiện hallucination hoặc đo chất lượng model.
Output diffing
Kỹ thuật so sánh sự khác biệt giữa các lần sinh câu trả lời để phân tích tính nhất quán của model.
Reasoning path tracing
Theo dõi từng bước suy luận của model/agent để nhận diện lỗi logic trong chuỗi suy luận nhiều bước.
Model Context Protocol (MCP)
Giao thức chuẩn hóa cách AI agent kết nối tới công cụ/nguồn dữ liệu ngoài (MCP server).
Strands Agents / AWS Agent Squad
Framework mã nguồn mở của AWS để xây hệ thống multi-agent với quản lý memory/state và tool integration.
LoRA (Low-Rank Adaptation) / Adapter
Kỹ thuật parameter-efficient fine-tuning: tùy biến model với chi phí huấn luyện thấp hơn nhiều so với fine-tune toàn bộ tham số.
Model card
Tài liệu (có thể tạo tự động qua SageMaker AI) ghi lại mục đích, giới hạn, và đặc tính của một FM phục vụ tuân thủ/quản trị.
Data lineage
Khả năng theo dõi phả hệ/nguồn gốc dữ liệu xuyên suốt pipeline, thường dùng AWS Glue để tự động hóa.

RAG / Dữ liệu / Vector search

Retrieval Augmented Generation (RAG)
Kỹ thuật truy xuất dữ liệu liên quan rồi đưa vào prompt để mô hình sinh câu trả lời có căn cứ.
Embedding
Biểu diễn vector số học của văn bản/dữ liệu, dùng để so sánh độ tương đồng ngữ nghĩa.
Chunking
Chia nhỏ tài liệu thành các đoạn (fixed-size/semantic/hierarchical) trước khi tạo embedding cho RAG.
Hybrid search
Kết hợp vector search (ngữ nghĩa) và keyword search (khớp từ khóa chính xác) để tăng độ chính xác truy xuất.
Reranking
Sắp xếp lại kết quả truy xuất ban đầu theo mức độ liên quan thực sự bằng một mô hình chuyên biệt.
Query expansion / decomposition / transformation
Các kỹ thuật xử lý truy vấn: mở rộng, phân rã thành truy vấn nhỏ hơn, hoặc biến đổi truy vấn để cải thiện kết quả truy xuất.
Amazon OpenSearch Service
Dịch vụ tìm kiếm/phân tích hỗ trợ vector search, hybrid search, metadata filtering, tích hợp Neural plugin với Bedrock.
Amazon Aurora + pgvector
Cơ sở dữ liệu quan hệ PostgreSQL với extension pgvector để lưu và tìm kiếm vector embedding.
Amazon Kendra
Dịch vụ tìm kiếm doanh nghiệp (enterprise search) hỗ trợ query expansion và semantic search.
Vector store operational management
Giám sát hiệu năng, tối ưu index tự động và validate chất lượng dữ liệu cho vector database.

Orchestration / Compute / Enterprise Integration

AWS Lambda
Dịch vụ serverless compute, chạy code theo sự kiện mà không cần quản lý server.
Amazon API Gateway (REST/HTTP/WebSocket)
Dịch vụ quản lý API; WebSocket API dùng cho giao tiếp hai chiều/streaming thời gian thực.
AWS Step Functions
Dịch vụ orchestration dạng state machine; hỗ trợ circuit breaker pattern, ReAct pattern, Wait for Callback.
Circuit breaker pattern
Mẫu thiết kế tạm ngắt gọi tới một thành phần đang lỗi liên tục để tránh lỗi lan truyền, tự phục hồi khi thành phần đó ổn định trở lại.
Graceful degradation
Chiến lược giảm cấp độ dịch vụ có kiểm soát (ví dụ chuyển sang model dự phòng) thay vì để hệ thống sập hoàn toàn khi có sự cố.
Amazon EventBridge
Dịch vụ event bus, định tuyến sự kiện giữa các service theo rule tùy chỉnh — nền tảng cho kiến trúc event-driven.
AWS AppConfig
Quản lý cấu hình động (feature flag, tham số, model provider) với validate schema, rollout an toàn và rollback.
AWS Outposts / AWS Wavelength
Hạ tầng AWS mở rộng ra on-premises (Outposts) hoặc ra rìa mạng viễn thông (Wavelength) cho các yêu cầu hybrid/edge và data residency.
AWS Amplify
Bộ công cụ xây dựng ứng dụng web/mobile full-stack, hỗ trợ UI khai báo tích hợp nhanh với backend GenAI.
Amazon Q Developer
AI assistant hỗ trợ lập trình: sinh/tái cấu trúc code, gợi ý code, kiểm thử, tối ưu hiệu năng, tùy biến theo coding convention nội bộ.
AWS CDK
Bộ công cụ định nghĩa hạ tầng dưới dạng code (Infrastructure as Code) bằng ngôn ngữ lập trình quen thuộc.

Bảo mật / Quản trị / Tuân thủ

IAM (Identity and Access Management)
Dịch vụ quản lý danh tính, phân quyền qua role/policy/permissions boundary/condition key.
VPC Endpoint (Interface/Gateway)
Cho phép truy cập dịch vụ AWS qua đường truyền private trong VPC, không qua internet công cộng.
AWS Lake Formation / LF-Tags
Quản trị data lake với kiểm soát truy cập cột/bảng dựa trên tag, xuyên nhiều tài khoản.
AWS CloudTrail
Ghi log mọi API call phục vụ audit trail và data lineage.
Amazon Macie
Tự động phát hiện và phân loại dữ liệu nhạy cảm (PII) trong Amazon S3.
Personally Identifiable Information (PII)
Thông tin định danh cá nhân cần được bảo vệ/redact trong dữ liệu và phản hồi của AI.
Prompt injection / Jailbreak
Kỹ thuật tấn công cố gắng thao túng FM bỏ qua chỉ dẫn/guardrail ban đầu để sinh nội dung không mong muốn.
Bias drift
Hiện tượng độ thiên vị (bias) của model thay đổi/tăng theo thời gian, cần giám sát liên tục thay vì chỉ đánh giá một lần.
Data residency
Yêu cầu dữ liệu chỉ được lưu trữ/xử lý trong một khu vực địa lý/pháp lý nhất định.

Observability / ML Ops / Testing

Amazon CloudWatch
Dịch vụ giám sát: Logs, Logs Insights, Alarms, composite alarm, anomaly detection, dashboard.
AWS X-Ray
