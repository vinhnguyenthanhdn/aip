1Amazon Bedrock & Foundation Model (FM)

Amazon Bedrock là dịch vụ fully-managed cho phép truy cập nhiều foundation model (FM) — mô hình nền tảng quy mô lớn — từ nhiều nhà cung cấp (Anthropic Claude, Amazon Nova, Amazon Titan...) thông qua một API thống nhất, không cần tự quản lý hạ tầng GPU.

Các API gọi mô hình chính

  • InvokeModel — gọi mô hình đồng bộ, trả về toàn bộ kết quả một lần.
  • InvokeModelWithResponseStream — trả kết quả dạng stream (từng phần), dùng để hiển thị phản hồi "gõ chữ dần" theo thời gian thực, giảm độ trễ cảm nhận (perceived latency) cho ứng dụng chat.
  • Converse / ConverseStream — API hội thoại thế hệ mới, chuẩn hóa format request/response giữa các FM khác nhau (không cần định dạng payload riêng cho từng nhà cung cấp mô hình), hỗ trợ multi-turn bằng cách truyền mảng messages.
Khi đề bài yêu cầu "streaming response" cho trải nghiệm người dùng real-time: đáp án đúng gần như luôn kết hợp InvokeModelWithResponseStream/ConverseStream với API Gateway WebSocket API hoặc Lambda response streaming — KHÔNG phải REST API + client-side polling.

Model access & Inference profile

  • Model access — mỗi tài khoản/Region phải được cấp quyền bật (enable) từng FM trước khi có thể invoke.
  • Cross-Region Inference (CRI) / Inference profile — cho phép request được tự động định tuyến và xử lý ở một tập Region khác (ví dụ profile eu.anthropic.claude...) để tăng khả năng chịu tải mà vẫn giữ dữ liệu trong một châu lục/khu vực pháp lý cụ thể (ví dụ chỉ các Region thuộc EU).
  • Application inference profile — cho phép gắn tag, theo dõi chi phí, và áp policy theo từng use case cụ thể trên cùng một FM.
  • Prompt Router (Intelligent Prompt Routing) — tự động phân tích độ phức tạp của prompt để định tuyến câu hỏi đơn giản tới mô hình nhỏ/rẻ và câu hỏi phức tạp tới mô hình lớn/mạnh hơn, tối ưu chi phí mà không cần tự viết logic phân loại.

On-Demand vs Provisioned Throughput

  • On-Demand — trả tiền theo mỗi token, phù hợp tải không ổn định, có thể bị throttle khi vượt hạn mức.
  • Provisioned Throughput — mua trước công suất cố định theo Model Unit (MU) để đảm bảo throughput ổn định cho tải cao, liên tục (ví dụ 10.000 request/giờ trong giờ hành chính). Được cấu hình qua API CreateProvisionedModelThroughput.
Bẫy thường gặp: đã mua Provisioned Throughput nhưng CloudWatch vẫn cho thấy capacity đó "unused" trong khi request on-demand vẫn bị throttle → nguyên nhân kinh điển là code vẫn gọi modelId gốc (on-demand) thay vì ARN của provisioned model mà CreateProvisionedModelThroughput trả về. Sửa bằng cách thay tham số modelId bằng ARN đó, không phải bằng cách tăng MU hay thêm retry.

Latency-optimized inference & Prompt caching

Đặt tham số hiệu năng (performanceConfig.latency = "optimized") giúp giảm độ trễ inference cho các use case tương tác thời gian thực. Prompt caching lưu lại phần ngữ cảnh lặp lại (ví dụ system prompt, tài liệu nền) giữa các lần gọi để giảm chi phí và độ trễ khi xử lý các câu hỏi có phần ngữ cảnh giống nhau lặp lại nhiều lần.

2Prompt Engineering & Prompt Management

Kỹ thuật viết prompt

  • Zero-shot — yêu cầu mô hình thực hiện tác vụ mà không cung cấp ví dụ mẫu.
  • One-shot / Few-shot — cung cấp một hoặc vài ví dụ mẫu trong prompt để định hướng định dạng/phong cách đầu ra.
  • Chain-of-Thought (CoT) — yêu cầu mô hình "suy nghĩ từng bước" (step-by-step reasoning) trước khi đưa ra kết luận, giúp tăng độ chính xác cho các tác vụ suy luận phức tạp và giảm hallucination khi kết hợp với việc yêu cầu xác minh sự kiện (fact verification) trước khi tóm tắt.
  • Extended thinking — cấu hình một "ngân sách suy nghĩ" (thinking budget, tính bằng token) để mô hình dành thời gian suy luận nội bộ trước khi trả lời, hữu ích cho các bài toán cần giải thích rành mạch (explainability).
  • System prompt — phần chỉ dẫn cố định định hình vai trò/giọng văn/ràng buộc của mô hình xuyên suốt phiên hội thoại (ví dụ tùy biến tone theo từng business unit: legal, HR, finance).

Tham số suy luận (inference parameters)

  • Temperature — điều chỉnh mức "ngẫu nhiên/sáng tạo" của đầu ra. Temperature càng cao → đầu ra càng đa dạng nhưng cũng càng dễ hallucination. Không nên tăng temperature khi mục tiêu là giảm ảo giác/tăng độ chính xác.
  • Maximum token limit — giới hạn độ dài đầu ra; cần validate trước khi gửi request để tránh bị cắt (truncate) câu trả lời khi tài liệu đầu vào dài.

Amazon Bedrock Prompt Management, Flows & Agents so sánh nhanh

  • Prompt Management — quản lý phiên bản (versioning), biến (variables), và các biến thể (variants) của prompt tập trung; hỗ trợ workflow phê duyệt (approval) và audit trail, phù hợp khi cần quản trị hàng trăm prompt template dùng chung giữa nhiều team.
  • Bedrock Flows — công cụ kéo-thả (visual builder) để xây pipeline nhiều bước (input node → prompt node → output node), có thể gắn guardrail, knowledge base, Lambda vào từng bước mà không cần code orchestration thủ công.
  • Bedrock Agents — cho phép FM tự lập kế hoạch, gọi công cụ bên ngoài (action groups gọi Lambda/API), và tra cứu knowledge base để hoàn thành một nhiệm vụ nhiều bước (xem thêm mục 4).
Câu hỏi kiểu "quản lý hàng trăm prompt qua nhiều team, cần version control + approval workflow + audit trail, ít chi phí vận hành nhất" → đáp án gần như luôn là Bedrock Prompt Management, không phải tự dựng bằng S3 + Step Functions + EventBridge.

3RAG (Retrieval Augmented Generation) & Vector Database

RAG là kỹ thuật truy xuất thông tin liên quan từ một kho dữ liệu ngoài (thường qua tìm kiếm ngữ nghĩa) rồi đưa vào prompt để mô hình sinh câu trả lời có căn cứ (grounded), giúp giảm hallucination và cho phép trả lời dựa trên dữ liệu riêng/mới mà mô hình chưa từng được huấn luyện.

Amazon Bedrock Knowledge Bases

  • Dịch vụ fully-managed để xây RAG: tự động ingest tài liệu, chunk, tạo embedding, lưu vector, và cung cấp API truy xuất.
  • Retrieve — chỉ trả về các đoạn tài liệu liên quan (không sinh câu trả lời).
  • RetrieveAndGenerate / RetrieveAndGenerateStream — truy xuất + sinh câu trả lời cuối cùng trong một lệnh gọi, hỗ trợ source attribution/citation (trích dẫn nguồn) tự động.
  • Graph RAG (tích hợp Amazon Neptune Analytics) — mô hình hóa dữ liệu dạng đồ thị để nắm bắt quan hệ nhiều bước (multi-hop relationship) giữa các thực thể, phù hợp khi câu hỏi cần suy luận qua nhiều mối liên hệ gián tiếp (ví dụ dữ liệu tài chính liên quan chéo nhiều thực thể).

Chunking strategy (chiến lược chia nhỏ tài liệu)

  • Fixed-size chunking — chia theo số token cố định; đơn giản nhưng dễ cắt đứt các đoạn văn có liên kết ngữ nghĩa (ví dụ một điều khoản pháp lý bị chia làm đôi).
  • Semantic chunking — chia theo ranh giới ngữ nghĩa (breakpoint percentile threshold, buffer size theo số câu) để giữ trọn vẹn ý nghĩa một đoạn lập luận/điều khoản.
  • Hierarchical chunking — dùng chunk "cha" (ngữ cảnh rộng) và chunk "con" (chi tiết) để cân bằng giữa độ chính xác truy xuất và ngữ cảnh đầy đủ.
Bẫy thường gặp: khi tài liệu bị cắt sai ranh giới ngữ nghĩa (ví dụ lập luận pháp lý bị chia rời) gây thiếu ngữ cảnh/trích dẫn lỗi thời → đáp án đúng là đổi chunking strategy sang semantic boundaries rồi tạo lại embedding, KHÔNG phải chỉ tăng số chiều (dimensionality) của vector hay đổi datastore.

Tìm kiếm: Vector, Keyword & Hybrid

  • Vector/semantic search (k-NN) — tìm theo độ tương đồng ngữ nghĩa của embedding; mạnh về "hiểu ý" nhưng có thể bỏ sót các thuật ngữ/mã viết tắt chính xác (ví dụ thuật ngữ y khoa).
  • Keyword search — tìm khớp từ khóa chính xác; mạnh với thuật ngữ/mã số nhưng yếu về ngữ nghĩa.
  • Hybrid search — kết hợp cả hai, thường là lựa chọn tối ưu khi hệ thống báo cáo "bỏ sót thuật ngữ/mã viết tắt chính xác" nhưng "trả về quá nhiều kết quả tương tự ngữ nghĩa nhưng không liên quan".
  • Reranking — dùng một mô hình chuyên biệt (Amazon Bedrock Rerank API/reranker model) để sắp xếp lại kết quả truy xuất ban đầu theo mức độ liên quan thực sự trước khi đưa vào FM sinh câu trả lời — cải thiện chất lượng RAG với chi phí vận hành thấp hơn nhiều so với tự xây pipeline hai giai đoạn bằng SageMaker.

Lựa chọn Vector Database

  • Amazon OpenSearch Service / Serverless — vector search + metadata filtering + hybrid search, phù hợp dataset lớn (hàng chục triệu embedding), nhiều ngôn ngữ, cần độ trễ thấp và ít quản trị hạ tầng.
  • Amazon Aurora PostgreSQL + pgvector — phù hợp khi đã có sẵn dữ liệu quan hệ trong PostgreSQL và muốn kết hợp SQL truyền thống với similarity search trong cùng một database.
  • Amazon S3 Vectors — lưu trữ vector-native trên S3, tích hợp trực tiếp với Bedrock Knowledge Bases, chi phí thấp cho khối lượng lớn.
  • Amazon MemoryDB (Valkey/Redis OSS) — vector search trong bộ nhớ, độ trễ cực thấp; dùng thuật toán HNSW (Hierarchical Navigable Small World) khi index lớn cần approximate search nhanh, hoặc Flat/IVFFlat khi dataset nhỏ và cần độ chính xác tối đa (exact/near-exact search).
  • Amazon Neptune Analytics — khi bài toán cần truy vấn quan hệ đồ thị (Graph RAG) thay vì chỉ similarity search.

4Multi-Agent & Orchestration

Amazon Bedrock Agents

  • Action group — định nghĩa các "công cụ" (thường là Lambda hoặc REST API) mà agent có thể gọi để thực hiện hành động (ví dụ tra cứu đơn hàng, cập nhật hệ thống).
  • Agent có thể tích hợp trực tiếp với Knowledge Base để tra cứu tài liệu (RAG) và với action group để thực thi nghiệp vụ, giúp giảm mạnh operational overhead so với tự dựng orchestration bằng Step Functions/Lambda thủ công.
  • Trace events — bật để ghi lại từng bước suy luận/gọi công cụ của agent, phục vụ audit trail.
  • ReAct pattern (Reasoning + Acting) — mô hình xen kẽ giữa "suy luận" và "hành động" (gọi công cụ), là nền tảng cách Bedrock Agents vận hành nội bộ.

Kiến trúc multi-agent: Supervisor / Collaborator

Khi cần agent phục vụ nhiều domain khác nhau (ví dụ bệnh viện: khám lâm sàng, bảo hiểm, lịch hẹn), mẫu kiến trúc khuyến nghị là:

  • Một supervisor agent làm nhiệm vụ phân loại ý định (intent classification) ngôn ngữ tự nhiên của câu hỏi.
  • Định tuyến câu hỏi tới các collaborator agent chuyên biệt theo từng domain, mỗi collaborator gắn với knowledge base riêng (data isolation) và dùng IAM filtering để kiểm soát quyền truy cập dữ liệu.
  • Mẫu này scale tốt hơn nhiều so với việc dùng nhiều supervisor độc lập chạy song song hoặc một agent tổng quát (general-purpose) với nhiều action group xử lý mọi domain.

Amazon Bedrock AgentCore

Nền tảng runtime cho agent "production-grade": cung cấp sẵn memory (nhớ ngữ cảnh xuyên phiên), identity (định danh/ủy quyền), event handling, và observability tích hợp sẵn — giúp agent hỗ trợ cả invocation đồng bộ lẫn event-driven mà không cần tự xây state machine (Step Functions) + DynamoDB để lưu state như cách làm thủ công truyền thống.

Model Context Protocol (MCP)

  • MCP là giao thức chuẩn hóa cách AI agent kết nối tới các "công cụ"/nguồn dữ liệu bên ngoài (MCP server), giúp tách biệt logic công cụ khỏi logic agent.
  • STDIO transport — giao tiếp qua input/output cục bộ, phù hợp chạy MCP server trên cùng máy/tiến trình với client (không phù hợp khi cần expose ra ngoài cho nhiều consumer/đối tác thứ ba).
  • Streamable HTTP transport — giao tiếp qua HTTP, phù hợp khi cần expose MCP server cho nhiều ứng dụng nội bộ và đối tác bên ngoài; nên đặt sau Amazon API Gateway và bảo vệ bằng OAuth 2.1 (qua Amazon Cognito) khi cần strict authentication/authorization cho nhiều bên dùng chung.
  • MCP server có thể host bằng AWS Lambda function URL (bật SigV4 + IAM auth) khi chỉ cần nội bộ AWS gọi, hoặc qua API Gateway khi cần expose rộng hơn ra ngoài AWS.

Orchestration hạ tầng: AWS Step Functions

  • Standard workflow — hỗ trợ chạy dài (tới 1 năm), có Wait for a Callback (waitForTaskToken) để tạm dừng chờ phê duyệt của con người rồi resume bằng SendTaskSuccess — mẫu chuẩn cho các luồng cần human-in-the-loop review.
  • Express workflow — tối ưu cho luồng ngắn, tần suất cao, chi phí thấp hơn nhưng không hỗ trợ callback dài hạn.
  • Parallel state — chạy nhiều nhánh xử lý đồng thời (ví dụ nhiều loại phân tích trên cùng một báo cáo) để giảm tổng thời gian xử lý so với xử lý tuần tự.
  • Giới hạn payload 256 KB giữa các state — khi output vượt hạn mức này (ví dụ dữ liệu trung gian giữa các agent), giải pháp chuẩn là lưu dữ liệu lớn vào Amazon S3 và chỉ truyền reference (S3 URI) giữa các state bằng ResultPath/ResultSelector, không phải nén dữ liệu bằng Lambda.

5Guardrails & Responsible AI

Amazon Bedrock Guardrails — các loại policy

  • Content filters — chặn nội dung độc hại theo danh mục (hate, insults, violence...) với ngưỡng cấu hình (low/medium/high).
  • Denied topics — định nghĩa chủ đề bị cấm hoàn toàn (ví dụ tư vấn đầu tư cụ thể) kèm câu ví dụ mẫu để mô hình nhận diện tốt hơn.
  • Word filters — chặn theo danh sách từ/cụm từ tùy chỉnh (ví dụ tên đối thủ cạnh tranh).
  • Sensitive information filters — phát hiện và xử lý PII (personally identifiable information) theo hai chế độ: mask (che thông tin, vẫn giữ ngữ cảnh) hoặc block (chặn toàn bộ request/response).
  • Contextual grounding check — so khớp câu trả lời với nguồn tài liệu tham chiếu để phát hiện hallucination (nội dung không có căn cứ) và độ liên quan (relevance) của câu trả lời so với câu hỏi.
  • Automated Reasoning checks — dùng suy luận hình thức (formal/logic-based) để xác minh tính đúng đắn của câu trả lời theo một tập quy tắc định trước, giảm hallucination trong các domain có quy tắc rõ ràng.
Khi một use case cần nhiều mức xử lý khác nhau cho nhiều loại nội dung nhạy cảm (ví dụ: chặn nội dung độc hại ở mức trung bình, che PII trong response nhưng chặn thông tin tài chính trong input, đồng thời log lại để audit) → thường chỉ cần MỘT guardrail cấu hình đa chính sách (multiple filter/policy trong cùng một guardrail), KHÔNG cần tạo nhiều guardrail rồi nối chuỗi bằng Step Functions — cách đó vừa tốn công vừa tăng operational overhead không cần thiết.

Guardrail vận hành & giám sát

  • Detect mode vs Block mode — thường dùng "detect" (chỉ ghi nhận, không chặn) trong giai đoạn dev/test để đánh giá tác động, rồi chuyển sang "block"/"mask" khi lên production.
  • Cross-Region guardrail (guardrail profile) — cho phép guardrail được áp dụng nhất quán qua nhiều Region, hỗ trợ failover.
  • Metric giám sát: InvocationsIntervened (số lần guardrail can thiệp), dimension GuardrailContentSource — theo dõi qua Amazon CloudWatch alarms để phát hiện discrepancy (ví dụ chênh lệch tỷ lệ can thiệp giữa các nhóm nhân khẩu học, phục vụ đánh giá fairness).

Trách nhiệm giải trình (Responsible AI) khác

  • Fairness & Bias detection — dùng Amazon SageMaker Clarify để phân tích và tạo báo cáo về bias trong kết quả mô hình (ví dụ chênh lệch gợi ý sản phẩm giữa các nhóm nhân khẩu học), publish metric vào CloudWatch.
  • Human-in-the-loop — Amazon Augmented AI (A2I) định tuyến các kết quả có độ tin cậy thấp (low confidence) tới người review; kết hợp với Amazon Textract cho bài toán trích xuất dữ liệu từ tài liệu scan.
  • LLM-as-a-judge — dùng một FM khác (thường mạnh hơn, ví dụ Claude Sonnet) đóng vai "giám khảo" để tự động chấm điểm câu trả lời theo tiêu chí (độ chính xác, mức phù hợp), kết hợp với review của con người cho các trường hợp biên (edge case) — mô hình đánh giá lai (hybrid evaluation) này vừa tăng độ bao phủ vừa giảm chi phí so với 100% con người chấm thủ công.

6Model Evaluation & Observability

Amazon Bedrock Evaluation

  • Automatic evaluation — dùng metric có sẵn (built-in) như độ chính xác, độ hoàn chỉnh (completeness), hoặc LLM-as-a-judge để so sánh nhiều FM/nhiều biến thể prompt trên cùng bộ dữ liệu chuẩn.
  • Human evaluation — con người trực tiếp chấm điểm, dùng khi cần đánh giá chất lượng hội thoại phức tạp.
  • Retrieve-only evaluation — chỉ đánh giá chất lượng bước truy xuất (context relevance, context coverage) của một hệ RAG.
  • Retrieve-and-generate evaluation — đánh giá toàn bộ pipeline RAG từ truy xuất tới câu trả lời cuối, dùng các metric như precision@k, faithfulness, citation precision.
  • Khi cần so sánh nhiều chiến lược chunking + nhiều FM cùng lúc và enforce ngưỡng chất lượng trước khi deploy → nên gộp thành các evaluation job chạy trên cùng dataset chuẩn với LLM-as-a-judge, tích hợp vào pipeline CI/CD để tự động chặn (block) release không đạt ngưỡng.

Observability: theo dõi token, chi phí & bất thường

  • Model invocation logging — ghi log input/output (text, image) của mọi lệnh gọi Bedrock vào Amazon S3/CloudWatch Logs, là nền tảng cho audit trail và phát hiện hallucination hậu kiểm.
  • InputTokenCount / OutputTokenCount — metric CloudWatch theo dõi mức tiêu thụ token; kết hợp CloudWatch Logs Insights để phân tích theo từng tool/tính năng cụ thể khi có nhiều tool integration trong một ứng dụng.
  • CloudWatch anomaly detection alarm — tự động điều chỉnh baseline theo pattern lưu lượng thay đổi theo thời gian, ưu việt hơn alarm với ngưỡng cố định (static threshold) khi traffic pattern không ổn định.
  • Embedded Metric Format (EMF) — cách phát custom metric hiệu quả trực tiếp từ log, dùng trong CloudWatch Application Insights để theo dõi các metric nghiệp vụ tùy biến (chất lượng gợi ý, latency theo loại request/user segment).
  • AWS X-Ray — distributed tracing giúp xác định thành phần nào trong chuỗi service gây ra latency, nên dùng khi cần "trace request qua nhiều service boundary" và tương quan hiệu năng với đặc điểm của từng FM.
  • Amazon Managed Grafana / Amazon QuickSight — trực quan hóa dashboard cho nhiều nhóm người dùng (kỹ thuật & business), có thể kết hợp metric kỹ thuật (CloudWatch) với metric nghiệp vụ (nguồn ngoài) trong cùng dashboard, cấu hình composite alarm/anomaly detection để cảnh báo khi hai loại metric cùng lệch bất thường.
Bẫy thường gặp: đề bài yêu cầu giám sát "gần thời gian thực" + "ít công sức phát triển nhất" cho hallucination/chi phí bất thường → ưu tiên bật model invocation logging + contextual grounding check của Guardrails + CloudWatch anomaly detection alarm (toàn bộ đều là tính năng có sẵn), thay vì tự xây pipeline Glue/Athena hoặc SageMaker Model Monitor riêng để phân tích log thủ công.

7Hiệu năng, Khả năng mở rộng & Tối ưu chi phí

  • Caching — dùng Amazon ElastiCache/MemoryDB hoặc OpenSearch k-NN để cache câu trả lời cho các câu hỏi ngữ nghĩa tương đương (semantically equivalent) nhằm giảm số lần gọi FM trùng lặp; tìm kiếm gần đúng bằng vector similarity hiệu quả hơn nhiều so với so khớp chuỗi (LIKE) hay chuẩn hóa từ khóa thủ công.
  • Retry strategy thích ứng — adaptive retry với exponential backoff + jitter kết hợp circuit breaker (tạm ngắt retry khi tỷ lệ lỗi vượt ngưỡng) là chuẩn để xử lý throttling khi traffic đạt đỉnh, tốt hơn nhiều so với retry với delay cố định.
  • Response streaming resilience — khi stream bị ngắt giữa chừng, nên buffer các chunk đã nhận và resume từ điểm ngắt thay vì phải gọi lại toàn bộ request.
  • Cross-Region inference để phân tán tải khi một Region đạt service quota, kết hợp failover tự động thay vì chỉ tăng provisioned throughput tại một Region duy nhất.
  • Model routing theo độ phức tạp — dùng Bedrock Intelligent Prompt Routing để tự động gửi câu hỏi đơn giản tới mô hình nhỏ, câu hỏi phức tạp tới mô hình lớn, tối ưu chi phí mà vẫn giữ chất lượng, thay vì tự viết logic keyword-based routing hoặc dùng một model duy nhất cho mọi loại câu hỏi.
  • Batch inference — dùng cho khối lượng lớn không yêu cầu phản hồi tức thời (ví dụ xử lý hàng loạt tài liệu) để tối ưu chi phí so với real-time endpoint.
  • SageMaker AI endpoint types — real-time (độ trễ thấp, luôn sẵn sàng, phù hợp GPU chuyên dụng), serverless (tự động scale-to-zero, phù hợp tải không đều), asynchronous (xử lý ngầm cho payload lớn/thời gian xử lý dài).

8Bảo mật, Quản trị dữ liệu & Tuân thủ

Kết nối private & kiểm soát truy cập

  • VPC endpoint (interface endpoint) cho Amazon Bedrock — đảm bảo mọi lệnh gọi tới Bedrock đi qua đường truyền private trong VPC của khách hàng, không qua internet công cộng; đây là lựa chọn chuẩn khi đề yêu cầu "chỉ dùng private connectivity", thay vì NAT gateway (vẫn đi qua public endpoint) hoặc để public fallback.
  • AWS Lake Formation với LF-Tags — kiểm soát truy cập dữ liệu ở mức cột (column-level) và hàng/bảng xuyên nhiều tài khoản AWS bằng cách gắn tag cho database/table rồi cấp quyền theo tag — linh hoạt và ít bảo trì hơn nhiều so với cấp quyền trực tiếp (direct grant) trên từng bảng.
  • IAM condition keys — ràng buộc chi tiết (ví dụ chỉ cho phép invoke một GuardrailIdentifier hoặc ModelId cụ thể) để đảm bảo mọi lệnh gọi Bedrock đều đi qua guardrail bắt buộc.
  • Attribute-based access control (ABAC) — cấp quyền theo thuộc tính (ví dụ phòng ban) thay vì liệt kê từng tài nguyên, giảm số lượng policy cần quản lý khi tổ chức có nhiều team/nhiều tài nguyên tương tự nhau.

Service Control Policy (SCP) & Data residency

  • SCP (AWS Organizations) — giới hạn hành động ở mức tổ chức, ví dụ chỉ cho phép dùng một số FM/Region nhất định để đảm bảo data residency (dữ liệu không rời khỏi khu vực pháp lý yêu cầu, ví dụ EU).
  • Khi SCP chặn nhầm một inference profile CRI hợp lệ (ví dụ lỗi "explicitly denies the action" dù đã enable model access) → cần rà soát và mở rộng điều kiện SCP để cho phép đúng ARN của inference profile theo khu vực (ví dụ pattern eu.*) kết hợp xác nhận IAM role có quyền invoke qua đúng profile đó — đây là lỗi cấu hình SCP quá chặt, không phải lỗi thiếu model access.
  • Multi-Region/Multi-continent architecture — khi dữ liệu độc quyền của khách hàng "không được rời khỏi khu vực địa lý", nên triển khai riêng theo từng khu vực (regional deployment) thay vì một kiến trúc tập trung toàn cầu.

Bảo vệ dữ liệu nhạy cảm (PII)

  • Amazon Macie — tự động phát hiện và phân loại dữ liệu nhạy cảm (PII, dữ liệu tài chính) trong S3.
  • Amazon Comprehend / Comprehend Medical — trích xuất thực thể (entity) và phát hiện PII trong văn bản, hỗ trợ redact trước khi đưa dữ liệu vào FM.
  • Với hệ thống RAG cần phân quyền hiển thị PII khác nhau theo vai trò người dùng (ví dụ bác sĩ thấy đầy đủ, kỹ sư bị redact) → giải pháp gọn nhất là gọi ApplyGuardrail tương ứng với nhóm người dùng (Cognito group) ngay tại thời điểm hỏi đáp, thay vì duy trì nhiều bản sao knowledge base đã redact sẵn.

Audit trail

  • AWS CloudTrail — ghi lại mọi API call (management & data event) để phục vụ audit; CloudTrail Insights phát hiện pattern bất thường; CloudTrail Lake cho phép truy vấn log tập trung xuyên nhiều tài khoản.
  • Kết hợp S3 server access logging khi cần audit chi tiết ở mức file/object, và SSE-KMS để mã hóa dữ liệu tại chỗ (encryption at rest) bằng khóa do khách hàng quản lý.

9Triển khai, CI/CD & Kiến trúc đa Region

  • AWS CDK cho Bedrock — dùng aws_bedrock.FoundationModel.fromFoundationModelId() khi muốn dễ dàng đổi FM giữa các môi trường (dev/prod) chỉ bằng tham số, thay vì aws_bedrock.ProvisionedModel.fromProvisionedModelArn() vốn gắn cứng với một provisioned model ARN cụ thể (chỉ phù hợp production ổn định).
  • Một CDK app + một CodePipeline nhiều deployment stage (mỗi stage một environment, dùng CodeBuild deploy action) là mẫu chuẩn để tránh trùng lặp hạ tầng khi cần "dễ dàng chuyển đổi FM để test giữa các environment".
  • Canary deployment cho model version — dùng EventBridge + Step Functions để tự động dịch chuyển traffic theo giai đoạn (staged traffic shifting), theo dõi CloudWatch metric ở mỗi giai đoạn, tự động tăng traffic nếu đạt ngưỡng và tự động rollback nếu hiệu năng giảm — không cần can thiệp thủ công.
  • AWS AppConfig — quản lý configuration động (model provider, feature flag, tham số như temperature/token limit) với khả năng validate bằng JSON schema, rollout an toàn và rollback, phù hợp khi cần đổi model provider/tham số "không cần deploy lại code" và có kiểm soát rủi ro.
  • AWS Service Catalog — chuẩn hóa các pattern hạ tầng đã được duyệt (bảo mật, observability, RAG theo AWS Well-Architected Generative AI Lens) thành portfolio/product tái sử dụng, versioned, cho nhiều business unit cùng dùng mà vẫn đảm bảo governance nhất quán.
  • Multi-language / multi-runtime consistency — khi một ứng dụng chạy trên nhiều SDK (ví dụ Lambda Python + EKS JavaScript) nhưng cần cùng FM, cùng cơ chế xác thực (IAM role), và giữ ngữ cảnh hội thoại nhất quán → nên dùng chung Converse API (chuẩn hóa qua các SDK ngôn ngữ khác nhau) và tự truyền lại lịch sử hội thoại trong mảng messages của mỗi request.

10Bảng thuật ngữ AWS (Glossary)

Tra cứu nhanh toàn bộ dịch vụ/API/khái niệm AWS xuất hiện trong bộ đề. Gõ để lọc.

Generative AI / Bedrock

Amazon Bedrock
Dịch vụ fully-managed truy cập nhiều foundation model qua một API thống nhất, không cần tự vận hành hạ tầng GPU.
Foundation Model (FM)
Mô hình nền tảng quy mô lớn (LLM, mô hình đa phương thức...) được huấn luyện trước, dùng chung cho nhiều tác vụ.
Amazon Bedrock Guardrails
Lớp kiểm soát an toàn nội dung: content filter, denied topics, PII filter, contextual grounding check, word filter.
Amazon Bedrock Knowledge Bases
Dịch vụ RAG managed: tự ingest, chunk, tạo embedding, lưu vector và cung cấp API truy xuất/sinh câu trả lời.
Amazon Bedrock Agents
Cho phép FM tự lập kế hoạch và gọi công cụ (action group) hoặc knowledge base để hoàn thành nhiệm vụ nhiều bước.
Amazon Bedrock AgentCore
Runtime cho agent production-grade với memory, identity, event handling, observability tích hợp sẵn.
Amazon Bedrock Flows
Công cụ kéo-thả xây pipeline nhiều bước (input/prompt/output node) không cần code orchestration.
Amazon Bedrock Prompt Management
Quản lý version, biến, biến thể của prompt template tập trung kèm workflow phê duyệt & audit trail.
Prompt Router / Intelligent Prompt Routing
Tự động định tuyến câu hỏi đơn giản tới mô hình nhỏ, câu hỏi phức tạp tới mô hình lớn để tối ưu chi phí.
Application Inference Profile
Định danh gắn tag/theo dõi chi phí và policy riêng cho một use case cụ thể trên cùng một FM.
Cross-Region Inference (CRI)
Định tuyến request tự động qua một tập Region khác để tăng khả năng chịu tải, vẫn giữ dữ liệu trong khu vực pháp lý cho phép.
Provisioned Throughput / Model Unit (MU)
Mua trước công suất cố định để đảm bảo throughput ổn định cho tải cao liên tục, tạo qua CreateProvisionedModelThroughput.
Amazon Bedrock Model Evaluation
Tạo evaluation job so sánh FM/prompt bằng metric tự động (kể cả LLM-as-a-judge) hoặc đánh giá của con người.
Amazon Bedrock Rerank API
Sắp xếp lại kết quả truy xuất RAG theo mức độ liên quan thực sự trước khi đưa vào FM.
Amazon Bedrock Custom Model Import
Đưa một mô hình tùy chỉnh/tự huấn luyện (ví dụ từ SageMaker) vào chạy trong Amazon Bedrock.
Amazon Bedrock Studio
Môi trường làm việc trực quan để thử nghiệm prompt và xây dựng ứng dụng GenAI trên Bedrock.
InvokeModel / InvokeModelWithResponseStream
API gọi FM đồng bộ (trả toàn bộ kết quả) hoặc dạng stream (trả từng phần theo thời gian thực).
Converse API / ConverseStream
API hội thoại chuẩn hóa format giữa nhiều FM, hỗ trợ multi-turn qua mảng messages.
Retrieve / RetrieveAndGenerate(Stream)
API của Knowledge Bases: chỉ truy xuất tài liệu, hoặc truy xuất + sinh câu trả lời kèm trích dẫn nguồn.
Amazon Titan
Dòng foundation model của AWS, bao gồm Titan Embeddings dùng để tạo vector embedding.
Amazon Nova
Dòng foundation model đa phương thức của AWS (ví dụ Amazon Nova Pro).
Anthropic Claude
Họ foundation model của Anthropic (Claude 3 Haiku, Sonnet...), khả dụng qua Amazon Bedrock.
Temperature
Tham số điều chỉnh mức ngẫu nhiên/sáng tạo của đầu ra mô hình; càng cao càng dễ hallucination.
Chain-of-Thought (CoT)
Kỹ thuật prompt yêu cầu mô hình suy luận từng bước trước khi kết luận để tăng độ chính xác.
Extended thinking
Cấu hình ngân sách token để mô hình suy luận nội bộ trước khi trả lời, hỗ trợ explainability.
Prompt caching
Lưu lại phần ngữ cảnh lặp lại giữa các lần gọi để giảm chi phí và độ trễ.
Hallucination
Hiện tượng mô hình sinh ra nội dung sai sự thật hoặc không có căn cứ trong nguồn dữ liệu.
Grounding / Contextual grounding check
Cơ chế đối chiếu câu trả lời với nguồn tham chiếu để phát hiện hallucination.
Automated Reasoning checks
Tính năng Guardrails dùng suy luận hình thức để xác minh tính đúng đắn theo bộ quy tắc định trước.
LLM-as-a-judge
Dùng một FM khác (thường mạnh hơn) để tự động chấm điểm chất lượng câu trả lời theo tiêu chí.
Model Context Protocol (MCP)
Giao thức chuẩn hóa cách AI agent kết nối tới công cụ/nguồn dữ liệu ngoài (MCP server).

RAG / Dữ liệu / Vector search

Retrieval Augmented Generation (RAG)
Kỹ thuật truy xuất dữ liệu liên quan rồi đưa vào prompt để mô hình sinh câu trả lời có căn cứ.
Embedding
Biểu diễn vector số học của văn bản/dữ liệu, dùng để so sánh độ tương đồng ngữ nghĩa.
k-NN (k-nearest neighbor)
Thuật toán tìm k điểm dữ liệu gần nhất trong không gian vector — nền tảng của semantic search.
HNSW (Hierarchical Navigable Small World)
Thuật toán index vector cho approximate nearest neighbor search tốc độ cao trên tập dữ liệu lớn.
IVFFlat
Thuật toán index vector (Inverted File with Flat Compression), phù hợp dataset nhỏ cần độ chính xác cao.
Chunking
Chia nhỏ tài liệu thành các đoạn (fixed-size/semantic/hierarchical) trước khi tạo embedding cho RAG.
Hybrid search
Kết hợp vector search (ngữ nghĩa) và keyword search (khớp từ khóa chính xác) để tăng độ chính xác truy xuất.
Reranking
Sắp xếp lại kết quả truy xuất ban đầu theo mức độ liên quan thực sự bằng một mô hình chuyên biệt.
Graph RAG
RAG dựa trên dữ liệu dạng đồ thị để nắm bắt quan hệ nhiều bước (multi-hop) giữa các thực thể.
Amazon OpenSearch Service/Serverless
Dịch vụ tìm kiếm/phân tích hỗ trợ vector search (k-NN), hybrid search, metadata filtering.
Amazon Aurora + pgvector
Cơ sở dữ liệu quan hệ PostgreSQL với extension pgvector để lưu và tìm kiếm vector embedding.
Amazon S3 Vectors
Lưu trữ vector-native trên S3, tích hợp trực tiếp với Bedrock Knowledge Bases, chi phí thấp.
Amazon MemoryDB (Valkey/Redis OSS)
Cơ sở dữ liệu in-memory hỗ trợ vector search độ trễ cực thấp (HNSW/Flat index).
Amazon Neptune Analytics
Cơ sở dữ liệu đồ thị dùng cho Graph RAG và phân tích quan hệ nhiều bước.
Amazon Kendra
Dịch vụ tìm kiếm doanh nghiệp (enterprise search) hỗ trợ query expansion và semantic search.
Amazon DynamoDB Accelerator (DAX)
Lớp cache in-memory cho DynamoDB, tăng tốc đọc dữ liệu tần suất cao.

Orchestration / Compute

AWS Lambda
Dịch vụ serverless compute, chạy code theo sự kiện mà không cần quản lý server.
Amazon API Gateway (REST/HTTP/WebSocket)
Dịch vụ quản lý API; WebSocket API dùng cho giao tiếp hai chiều/streaming thời gian thực.
AWS Step Functions
Dịch vụ orchestration dạng state machine; Standard hỗ trợ chạy dài + callback, Express tối ưu cho luồng ngắn tần suất cao.
Wait for a Callback (waitForTaskToken)
Mẫu Step Functions tạm dừng workflow chờ phản hồi ngoài (ví dụ con người duyệt) rồi resume bằng SendTaskSuccess.
Amazon EventBridge
Dịch vụ event bus, định tuyến sự kiện giữa các service theo rule tùy chỉnh.
Amazon SQS / SNS
Dịch vụ hàng đợi tin nhắn (SQS) và thông báo pub/sub (SNS) cho kiến trúc bất đồng bộ.
Amazon ECS / EC2 Auto Scaling
Dịch vụ chạy container/máy ảo với khả năng tự động mở rộng theo tải.
AWS AppConfig
Quản lý cấu hình động (feature flag, tham số) với validate schema, rollout an toàn và rollback.
AWS Systems Manager Parameter Store
Lưu trữ tham số/cấu hình tập trung, đơn giản hơn AppConfig nhưng ít tính năng rollout/validate hơn.

Bảo mật / Quản trị / Tuân thủ

IAM (Identity and Access Management)
Dịch vụ quản lý danh tính, phân quyền qua role/policy/permissions boundary/condition key.
Attribute-based access control (ABAC)
Cấp quyền theo thuộc tính (ví dụ phòng ban) thay vì liệt kê từng tài nguyên.
AWS Organizations / SCP
Quản lý nhiều tài khoản AWS; Service Control Policy giới hạn hành động được phép ở mức tổ chức.
AWS IAM Identity Center
Quản lý tập trung quyền truy cập của người dùng/nhóm xuyên nhiều tài khoản AWS.
VPC Endpoint (Interface/Gateway)
Cho phép truy cập dịch vụ AWS qua đường truyền private trong VPC, không qua internet công cộng.
AWS Lake Formation / LF-Tags
Quản trị data lake với kiểm soát truy cập cột/bảng dựa trên tag, xuyên nhiều tài khoản.
AWS KMS / SSE-KMS
Dịch vụ quản lý khóa mã hóa; SSE-KMS là mã hóa phía server dùng khóa KMS cho dữ liệu tại chỗ.
Amazon Cognito
Dịch vụ xác thực người dùng (user pool), hỗ trợ OAuth cho ứng dụng và API.
AWS CloudTrail (Insights/Lake)
Ghi log mọi API call phục vụ audit; Insights phát hiện bất thường, Lake cho phép truy vấn log tập trung.
Amazon Macie
Tự động phát hiện và phân loại dữ liệu nhạy cảm (PII) trong Amazon S3.
Personally Identifiable Information (PII)
Thông tin định danh cá nhân cần được bảo vệ/redact trong dữ liệu và phản hồi của AI.
Data residency
Yêu cầu dữ liệu chỉ được lưu trữ/xử lý trong một khu vực địa lý/pháp lý nhất định.

Observability / ML Ops

Amazon CloudWatch
Dịch vụ giám sát: Logs, Logs Insights, Alarms, composite alarm, anomaly detection, dashboard.
Embedded Metric Format (EMF)
Định dạng log đặc biệt để CloudWatch tự trích xuất custom metric hiệu quả từ log.
AWS X-Ray
Dịch vụ distributed tracing giúp xác định thành phần gây latency qua nhiều service.
Amazon Managed Grafana
Dịch vụ Grafana managed để trực quan hóa dashboard đa nguồn dữ liệu.
Amazon QuickSight
Dịch vụ business intelligence/dashboard trực quan hóa dữ liệu.
Amazon SageMaker AI
Nền tảng ML end-to-end: huấn luyện, triển khai endpoint (real-time/serverless/async), Pipelines, Clarify, Model Monitor.
Amazon SageMaker Clarify
Công cụ phân tích và báo cáo fairness/bias trong dữ liệu và kết quả mô hình.
Amazon Comprehend / Comprehend Medical
Dịch vụ NLP trích xuất thực thể, phát hiện PII, phân tích sentiment; bản Medical chuyên biệt cho văn bản y tế.
Amazon Textract
Dịch vụ trích xuất văn bản/dữ liệu có cấu trúc từ tài liệu scan/ảnh.
Amazon Transcribe
Dịch vụ chuyển giọng nói thành văn bản, hỗ trợ streaming với partial results.
Amazon Rekognition
Dịch vụ phân tích hình ảnh/video, bao gồm kiểm duyệt nội dung (content moderation).
Amazon Augmented AI (A2I)
Dịch vụ định tuyến kết quả AI có độ tin cậy thấp tới con người review.
Amazon Q Business
AI assistant doanh nghiệp truy vấn dữ liệu nội bộ theo ngôn ngữ tự nhiên, tôn trọng phân quyền nguồn dữ liệu gốc.
Amazon Q Developer
AI assistant hỗ trợ lập trình, có thể tùy biến (customization) theo thư viện/coding convention nội bộ công ty.
